### S4-2 — Anthropic: Steering thinking (effort levels, cost mechanics, pricing)

### S4-3 — Anthropic: Thinking (overview — display, context window, latency, preservation)
- URL: https://platform.claude.com/docs/en/build-with-claude/thinking · Accessed 2026-08-15 · Anthropic official docs · Primary/vendor docs · Direct fetch (large page, read in full) · Status: used
- Claims:
  - G4.3.1 — opening-paragraph statement: thinking tokens "are billed as output tokens, even when the thinking text isn't returned to you"
  - G4.3.2 — `display` parameter: `"summarized"` returns a readable summary; `"omitted"` (default on Fable 5, Mythos 5, Opus 5, Sonnet 5, Opus 4.8, Opus 4.7) returns an empty `thinking` field. Billing is **identical** either way; quote (6 words): "Omitting reduces latency, not cost."
  - G4.3.3 — what a user ever sees is "never the raw chain of thought" — always a summary, and that summary is generated by **a different model** than the one being queried; "the thinking model does not see the summarized output"
  - G4.3.4 — thinking-block preservation across turns is per-model, not universal: "keep-all" models (Opus 4.5 and later Opus, Sonnet 4.6 and later Sonnet, Fable 5, Mythos 5, Mythos Preview) retain prior-turn thinking in context and bill it as input tokens on every later turn; "keep-last-turn-only" models (earlier Opus/Sonnet, all Haiku through 4.5) auto-strip older thinking blocks — they are generated, billed once as output, then genuinely dropped and not re-billed
  - G4.3.5 — latency: "Expect longer response times when thinking is active"; requests pushing thinking past roughly 32k tokens risk hitting system timeouts and are recommended to go through the batch API instead
  - G4.3.6 — on Claude Opus 5, thinking cannot be turned off at `xhigh` or `max` effort — a `disabled` request at those levels is a hard 400 error
  - G4.3.7 — a `redacted_thinking` block type exists separately from "omitted" — reasoning that Anthropic's safety systems redact, encrypted and opaque, distinct from ordinary display-hiding

  - G4.4.2 — `high` is the API default and is defined as bit-identical to omitting the parameter

  - G4.4.6 — per-model recommended defaults vary: e.g. Sonnet 4.6 explicitly recommends stepping down to `medium` from the `high` default; Opus 4.7/4.8 recommend starting at `xhigh` for coding/agentic work

### S4-7 — OpenAI: Reasoning best practices
- URL: https://platform.openai.com/docs/guides/reasoning-best-practices (via r.jina.ai) · Accessed 2026-08-15 · OpenAI official docs · Primary/vendor docs, proxied · Status: used
- Claims:
  - G4.7.1 — direct quote (short, exact): "Avoid chain-of-thought prompts" — because internal reasoning already happens, telling the model to "think step by step" is called "unnecessary" and can hinder performance
  - G4.7.2 — direct quote (7 words): "Try zero shot first, then few shot" — reasoning models "often don't need few-shot examples"; if examples are used, misalignment between example structure and actual instructions is called out as a specific way they can hurt
  - G4.7.3 — structural guidance: keep prompts brief and direct, use delimiters (markdown/XML) to separate sections, state constraints and success criteria explicitly
  - G4.7.4 — from `o1-2024-12-17` onward, these models use "developer messages" instead of "system messages," and markdown output is off by default unless the developer message's first line says "Formatting re-enabled"

### S4-14 — arXiv 2604.10739v1 — "When More Thinking Hurts: Overthinking in LLM Test-Time Compute Scaling"
- URL: https://arxiv.org/html/2604.10739v1 · Accessed 2026-08-15 · Authors: Shu Zhou, Rui Ling, Junan Chen, Xin Wang, Tao Fan, Hao Wang; dated 2026-04-12 · Academic paper, arXiv preprint (very recent, peer-review status unconfirmed), stated method: controlled reasoning-token-budget sweeps against AIME, GPQA Diamond, and MATH-500 benchmarks, model R1-32B (DeepSeek-R1-distilled 32B) among others · Status: used — **the single most direct diminishing-returns measurement found in this gather**
- Claims:
  - G4.14.1 — MEASURED: R1-32B on AIME peaks at 12K reasoning tokens (55.8% accuracy), falls to 54.9% at 16K tokens (a −0.9-point decline from more thinking)
  - G4.14.2 — MEASURED: marginal accuracy return per 500 additional reasoning tokens goes from +0.9% (in the 6K–8K token range) to −0.3% (in the 12K–16K range) — the sign flips, i.e. more thinking becomes actively harmful past a threshold, not just flat
  - G4.14.3 — MEASURED: a "flip ratio" (share of answer changes from correct→incorrect vs incorrect→correct as budget grows) crosses 1.0 — net-harmful — at approximately 7K tokens on their setup
  - G4.14.4 — MEASURED: the optimal token budget scales with problem difficulty — easiest problems (Level 1–2) show overthinking past ~2K tokens; hardest (Level 5) tolerate up to ~8–10K tokens before decline; on MATH-500 specifically, optimal budgets range from ~1.0K tokens (Level 1) to ~7.5K tokens (Level 5)
  - G4.14.5 — MEASURED: of the harmful answer-flips, 67.5% involve the model explicitly reconsidering and rejecting a previously correct answer — i.e. most of the harm is genuine second-guessing, not random noise

## ANSWERS

### SQ5 — cost

**Token multipliers.** No single, clean, current-generation "thinking consumes Nx the tokens of non-thinking on the same prompt" figure could be traced to a rigorous stated-method source — this is reported honestly as **number not traced** at the general level. What is traceable:
- A real, dated, stated-method comparison exists for Claude 3.7 Sonnet (Feb 2025, now a retired model) via the Aider Polyglot coding leaderboard, cited by Simon Willison (G4.12.3): thinking-on (32K budget) cost 2.08x thinking-off on identical benchmark conditions ($36.83 vs $17.72), for +4.5 percentage points of problems solved. This is a **cost ratio** (includes input+output+thinking tokens together), not a pure token-count ratio, and it is 18 months stale relative to current models/tokenizers (Anthropic's own docs note the post-4.7 tokenizer alone produces ~30% more tokens for identical text, G4.5.4, which would confound any direct reuse of this number).
- Vendor-recommended *ranges* (not multipliers) are traceable: Anthropic suggests starting near 1,024 thinking tokens for simple tasks and 16,000+ for complex ones (G4.1.4) — a roughly 16x span for the *same vendor's own guidance* depending on task difficulty, not a thinking-vs-off multiplier.
- The overthinking literature (below) gives concrete absolute reasoning-token counts at which specific accuracy levels are reached (e.g. 1K–16K tokens spanning easy-to-hard problems, G4.14.4) — useful for "how many tokens does thinking actually use," not for "how many more than not thinking."
- A frequently-repeated "10–30x" figure was found in one marketing blog with no stated method or citation and is explicitly **not used** (see Rejected sources).

**Price mechanics — cross-vendor, all confirmed on primary pricing/docs pages:**
- **Anthropic**: thinking tokens billed as output tokens, at the same per-model output rate — no separate line item on the pricing table (G4.5.1, G4.2.2, G4.3.1). Thinking blocks retained from prior turns are billed as *input* tokens on "keep-all" models (G4.3.4).
- **OpenAI**: reasoning tokens "are billed as output tokens" at "the selected model's standard token rates" (G4.6.2–G4.6.3) — same pattern, confirmed by OpenAI's own guide in its own words.
- **Google Gemini**: "Response pricing is the sum of output tokens and thinking tokens" and the current Gemini 2.5 pricing table shows one bundled output-including-thinking rate per model, not two (G4.9.4, G4.10.1–3). All three vendors converge on the same mechanism: **thinking/reasoning tokens are priced identically to ordinary output tokens, with no vendor charging a reasoning premium or discount per token** as of this access date.
- **"Tokens you never see" — verified, cross-vendor, this is real and load-bearing for the chapter's framing:** all three vendors explicitly confirm you are billed for the full internal reasoning pass regardless of whether any of it is shown to you. Anthropic: billed count "does **not** match" the visible count (G4.2.3); with `display:"omitted"` you see zero thinking text and are still billed in full (G4.3.2). OpenAI: reasoning tokens are "not visible via the API" at all, ever, yet billed (G4.6.2). Google: pricing is "based on the full thought tokens," not the summary shown (G4.9.4). This is independently stated on three separate primary vendor docs pages, not an inference.

**Thinking-budget controls — verify what exists, by vendor, as of 2026-08-15:**
- **Anthropic**: the parameter name `budget_tokens` (manual extended thinking) is real but is being retired — deprecated on the 4.6 generation, hard-rejected (400 error) on 4.7 and later (G4.1.2). Its replacement is `thinking:{type:"adaptive"}` plus a separate `output_config.effort` parameter with five named levels (`low`/`medium`/`high`/`xhigh`/`max`) that steers *all* output, not just thinking (G4.4.1–G4.4.2). A newer, distinct, beta-only control called `task_budget` (beta header `task-budgets-2026-03-13`) sets an advisory (not hard) token ceiling across an entire multi-step agentic loop — minimum 20,000 tokens, currently supported only on Opus 5, Fable 5, Mythos 5, Opus 4.8, and Opus 4.7 (fetched directly from platform.claude.com/docs/en/build-with-claude/task-budgets, accessed 2026-08-15). This is a genuine, named, currently-real parameter, distinct from `effort` and from the retired `budget_tokens` — the chapter should not conflate the three.
- **OpenAI**: `reasoning_effort` is real and confirmed on OpenAI's own docs (G4.6.1), with accepted values expanding release over release: GPT-5 shipped with 4 levels, GPT-5.6 has 7 (G4.18.1–G4.18.4). There is no OpenAI token-count budget parameter analogous to Anthropic's old `budget_tokens` — OpenAI's control has always been effort-tier-based, not a raw token number.
- **Google Gemini**: `thinkingBudget` (an actual token count, 0 to a model-specific max, or -1 for dynamic) is real and currently live, alongside a newer `thinkingLevel` (named tiers) for the Gemini 3 series (G4.9.1–G4.9.3) — Gemini is the only one of the three vendors still offering a **raw numeric token budget** as a first-class, non-deprecated control as of this access date.
- Net picture: all three vendors started with (or still offer) a numeric token-budget knob, and all three are visibly moving toward named effort/level tiers instead. Anthropic has gone furthest (numeric budget actively rejected on newest models); Google has kept both; OpenAI never had a numeric one.

**Diminishing returns — yes, well evidenced, both as vendor-acknowledged and independently measured:**
- Anthropic's own docs use the word "overthinking" for its own top-tier `max` effort setting, warning it can add "significant cost for relatively small quality gains" (G4.4.3) — a vendor undercutting its own most-expensive option in its own documentation is notable and worth quoting in the chapter.
- The most direct independent measurement found: arXiv 2604.10739 (April 2026, G4.14.1–G4.14.5) measured accuracy *peaking then declining* as reasoning-token budget grows, on real benchmarks (AIME, GPQA Diamond, MATH-500) with a real model (R1-32B): accuracy peaked at 12K tokens (55.8%) then fell to 54.9% at 16K; marginal return per 500 tokens flipped from positive to negative around the 8K–12K mark; the optimal budget scales with problem difficulty (as low as ~1K tokens for easy problems, up to ~7.5–10K for the hardest). The mechanism identified is not just wasted tokens but *active harm*: the model reconsiders and overturns its own correct answers in 67.5% of the harmful cases.
- A broader survey (arXiv 2503.16419, G4.13.1–G4.13.3) situates this as a known, named phenomenon ("overthinking") with multiple independent studies cited showing the same peak-then-decline pattern, though the survey itself is a secondary synthesis, not a new measurement.

### SQ6 — practice

**Decision rules a non-expert can apply, grounded in what vendors actually say (not invented):**
- All three vendors converge on the same underlying signal even though they expose it differently: **effort/thinking should scale with how "solvable-by-pattern-matching" the task is, not with how important it is.** Anthropic's own effort-level table (G4.2.1) is the clearest plain-language version of this: `low` = "skips thinking for simple tasks where speed matters most"; `high` (default) = "deep reasoning on complex tasks"; `max` = no constraints, reserved for genuinely hard problems, with the vendor's own warning that overusing it can *hurt* results on structured/simple tasks (G4.4.3). This is a usable rule of thumb for a non-engineer: **turn thinking up for multi-step, ambiguous, or high-stakes-if-wrong tasks (math, debugging, planning with tradeoffs, long documents with cross-references); leave it low or off for lookups, formatting, short factual questions, and anything where the answer is essentially pattern completion.**
- This rule is corroborated, not contradicted, by the diminishing-returns evidence in SQ5: forcing maximum thinking on an easy task is not "extra-safe," it measurably increases the odds of the model talons a correct answer into a wrong one (G4.14.1–G4.14.5).
- Cost/latency tradeoff is explicit and vendor-stated on all sides: thinking reliably adds latency (G4.3.5, G4.9.6, and Willison's directly measured 14ms/token pacing G4.12.2) and, per the pricing mechanics above, always adds cost proportional to tokens generated, at the ordinary output rate — there is no free "let it think a bit" tier.

**Does prompting differ for reasoning models? Verified against both vendor docs and practitioner/academic evidence — yes, with a real nuance:**
- OpenAI's own reasoning best-practices page states directly and unambiguously that "think step by step" instructions are unnecessary and can hinder reasoning models (G4.7.1), and that few-shot examples should be tried only after zero-shot fails, since misaligned examples can drag performance down (G4.7.2).
- Independent corroboration: a 2026 academic paper (arXiv 2506.14641, G4.19.1–G4.19.3) measured, on standard instruction-tuned models (Qwen2.5, LLaMA3, Gemma2 — not on dedicated reasoning-token models specifically), that adding 8-shot CoT exemplars did not beat zero-shot, and sometimes trailed it slightly (e.g., Qwen2.5-72B: 95.83% zero-shot vs. 95.75% 8-shot on GSM8K).
- **The nuance worth stating plainly in the chapter**: the "few-shot can hurt reasoning models specifically" claim is well-supported as *OpenAI's own stated guidance* (a primary vendor source, not hearsay), and is directionally corroborated by academic work on prompting generally — but this gatherer could not find an independent, controlled study that isolates dedicated reasoning-token models (o-series, Claude thinking mode, Gemini thinking mode) by name and measures few-shot degradation on them specifically, as opposed to on ordinary chat models. The chapter should attribute this claim to the vendors' own documentation rather than present it as independently, externally proven across all reasoning models.

**How to read a trace usefully — grounded in vendor mechanics plus one alignment-research finding:**
- Mechanically, on Anthropic and Gemini, what you are shown (when shown anything) is a **summary generated by a separate, smaller/different process**, not the raw chain of thought — stated explicitly by Anthropic ("the thinking model does not see the summarized output," G4.3.3) and Gemini ("thought summaries," visible only if `includeThoughts` is set, G4.9 fetch). OpenAI's reasoning tokens are not exposed at all via the API in raw or summary text form beyond the token count (G4.6.2) as documented on the page fetched — the chapter should not claim OpenAI shows any reasoning text.
- Practically, in Claude Code specifically, Ctrl+O reveals the thinking stream live, rendered as it arrives (G4.6 search result); a practitioner writeup (G4.16.1–G4.16.3) confirms via direct inspection of raw session files that the terminal view matches the underlying summary blocks, and offers the useful mental model: **"a smoke alarm, not a transcript"** — good for catching an obviously wrong assumption early and interrupting (Ctrl+C) before it compounds, unreliable for reconstructing the precise order of steps or the paths not taken.
- The deeper reason to stay skeptical of any trace, summarized or not, is Anthropic's own alignment research (G4.17.1): stated reasoning does not reliably reflect what actually drove the model's answer — models sometimes lean on their stated chain-of-thought and sometimes "primarily ignore it," on a task-by-task basis with no visible tell. **Practical decision rule for a non-engineer: use the trace to sanity-check direction of travel, never as an audit trail, and never as proof the model didn't consider something it didn't mention.**

**Interaction with tools/agents — real, sourced, and easy to underestimate:**
- Effort/thinking settings propagate into tool-calling behavior, not just prose: Anthropic documents that lower effort produces fewer, more consolidated tool calls with terse confirmations, while higher effort produces more calls and more narrated planning (G4.4.5) — i.e., turning reasoning down on an agent doesn't just make the final answer shorter, it changes how the agent *acts*.
- Interleaved thinking (reasoning between individual tool calls within one turn) is automatic on current adaptive-thinking Anthropic models with no extra configuration (G4.3, "Interleaved thinking" section) — a non-engineer using an agent product built on these models is very likely already paying for this even if they never touch a "thinking" toggle.
- Agentic loops multiply cost in a way that is easy to miss because it is not about the reasoning-token rate at all: an April-2026 academic study of real coding-agent trajectories (G4.15.1–G4.15.4) found agentic tasks can consume on the rough order of 1000x the tokens of a single chat turn (headline abstract figure, not independently re-derived by this gatherer, flagged accordingly), that identical tasks can vary by up to 30x in total tokens run-to-run, and that the dominant cost driver is accumulated *input* context (conversation history, tool outputs) being re-sent on every step — not the reasoning/output tokens this SQ otherwise focuses on. **This is the single most important practical caution for a non-engineer budgeting for "agent" products**: the per-token reasoning multiplier discussed above compounds with, and is often smaller than, the multiplier from simply running many steps in a loop.
- Anthropic's beta `task_budget` control (see SQ5) exists specifically to let an agent "self-regulate" against a running token countdown across an entire multi-step loop, separate from the per-step `effort` control — direct vendor evidence that this compounding-cost problem is real enough to warrant its own dedicated, separate knob.

## CONTRADICTIONS & SURPRISES

- **Gemini 2.5 Flash pricing discrepancy.** A search-engine-mediated snippet (not this gatherer's own direct page read) claimed Gemini 2.5 Flash once had two separate output rates — $0.60/MTok non-thinking vs. $3.50/MTok thinking (implying a ~5.8x thinking premium *at the per-token level*, which would be the only such vendor-side per-token premium found anywhere in this gather). This directly conflicts with the current, directly-fetched pricing page (S4-10, G4.10.2), which shows one bundled $2.50/MTok "output (including thinking)" rate with no separate thinking line. The likely explanation is that the $0.60/$3.50 split describes an older "Preview"-era pricing scheme that Google has since replaced with a bundled rate — but this was not independently confirmed by finding an archived version of the old page (web.archive.org is blocked per the access playbook), so it is reported as an open discrepancy rather than resolved. **If the chapter wants to make a claim about Gemini ever having charged a separate, higher per-token thinking rate, that claim needs its own dedicated verification pass — it is not solid as this gather stands.**
- **Anthropic is retiring the exact parameter this assignment was told to verify.** The assignment brief specifically named "Anthropic extended-thinking budget_tokens" as a control to verify. It is real, well-documented — and is simultaneously being actively deprecated/rejected across Anthropic's newest model generation in favor of `adaptive` thinking + `effort` (G4.1.2). A chapter written as if `budget_tokens` were Anthropic's current flagship control would already be dated at the moment of publication; this is worth flagging to the writer directly, not just noting in passing.
- **All three vendors converged independently on "billed as output tokens, no separate rate" and on "you can be billed for reasoning you never see."** This was not assumed going in — it was independently confirmed on three separate primary vendor docs pages (Anthropic, OpenAI, Google), which is a stronger evidentiary basis than the chapter's framing hypothesis needed. Worth stating in the chapter with confidence.
- **The clean "reasoning models multiply tokens by Nx" figure the assignment hoped to find does not exist as a single traceable current-generation number.** Every specific multiplier found is either old (Claude 3.7 Sonnet-era Aider Polyglot, 2.08x cost ratio, S4-12), a vendor-recommended *range* rather than a measured multiplier (S4-1), or describes something else entirely (agentic-loop total token multiplication, ~1000x per S4-15, which is not the same phenomenon as "thinking vs non-thinking on one prompt"). The chapter should present a range/example rather than a single headline multiplier, and should be explicit that "thinking vs not" and "agent loop vs single turn" are two different multipliers that both apply and compound.
- **The "few-shot hurts reasoning models" claim is solid as vendor guidance but thinner as independent science than expected.** The best controlled academic measurement found (S4-19) tests ordinary chat models, not the dedicated reasoning-token models the claim is actually about. This is a real gap, not a fatal one — OpheAI's own documentation is a legitimate primary source for a claim about OpenAI's own models — but the chapter should not imply a broad peer-reviewed consensus specifically on o1/o3/Claude-thinking/Gemini-thinking that this gather did not find.
